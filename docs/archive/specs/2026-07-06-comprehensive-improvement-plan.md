## [S5] P0: 同步稳定性

### [S5.1] 现状分析

当前同步架构：
- Supabase realtime subscription
- Last-write-wins + field-level merge
- Debounced push with exponential backoff
- Watermark-based dirty detection

### [S5.2] 已知问题

1. **Equal updatedAt 冲突** — 虽然已有 content tiebreaker，但极端情况仍可能丢失
2. **Realtime 延迟** — Supabase realtime 偶有延迟，导致短暂不一致
3. **离线队列** — 长时间离线后恢复，批量推送可能失败
4. **配置同步** — profiles 表的 config 同步是全量覆盖

### [S5.3] 改进方案

#### A. 同步健壮性
- **冲突日志** — 记录每次冲突的详情，供用户查看
- **手动冲突解决** — 当检测到冲突时，弹窗让用户选择保留哪个版本
- **同步状态指示器** — 在首页显示同步状态（已同步/同步中/有冲突）
- **离线队列持久化** — 将待推送的变更存入 AsyncStorage，重启后恢复

#### B. 增量同步优化
- **Config 字段级同步** — profiles.config 拆分为多个独立字段，避免全量覆盖
- **压缩传输** — 对大批量数据启用 gzip 压缩
- **批量分页** — 大数据量时分页拉取，避免一次性加载

#### C. 同步诊断
- **同步日志** — 记录最近 N 次同步操作的结果
- **手动重试按钮** — 在设置中显示最近错误和重试选项
- **数据一致性检查** — 定期校验本地和云端数据是否一致

### [S6.1] 现状分析

当前预算功能：
- 每月总预算
- 每日预算
- 分类预算（单个分类上限）
- BudgetPot 可视化

### [S6.2] 改进方案

- **周预算** — 支持按周设置预算
- **自定义周期** — 如"每两周"、"每季度"
- **年度预算** — 年度总预算，按月自动分配

#### B. 预算模板
- **预算方案切换** — 如"节省模式"、"正常模式"、"宽松模式"
- **季节性预算** — 不同月份自动调整（如春节、双十一）
- **预算复制** — 从上月复制预算设置

#### C. 预算可视化增强
- **预算进度条** — 每个分类的预算使用进度
- **剩余天数计算** — "按当前速度，本月还能花 X 元/天"
- **预算达成预测** — "按目前趋势，月底将超支 Y 元"
- **历史预算对比** — 过去 N 个月的预算执行情况

#### D. 预算提醒
- **阈值提醒** — 达到 50%/80%/100% 时推送通知
- **超支预警** — 每日检查并提醒
- **月底冲刺** — 最后 3 天提醒剩余预算

## [S7] P1: 性能优化

### [S7.1] 现状分析

- AsyncStorage 存储，已做分拆（entries/config 独立 key）
- Legend State 响应式更新
- 全量数据加载到内存

### [S7.2] 改进方案

#### A. 存储层升级
- **SQLite 迁移** — 从 AsyncStorage 迁移到 expo-sqlite
  - 支持索引查询，大数据量不卡
  - 支持复杂查询（按日期范围、分类、金额筛选）
  - 支持事务，保证数据一致性

#### B. 列表性能
- **虚拟列表** — 使用 FlashList 替代 FlatList
- **懒加载** — 只加载当前可见周期的数据
- **图片懒加载** — 头像等资源延迟加载

#### C. 启动优化
- **Splash Screen 优化** — 减少白屏时间
- **代码分割** — 按路由懒加载
- **预加载** — 预加载常用页面

#### D. 内存优化
- **数据分页** — 大数据量时分页加载
- **图片缓存** — 控制缓存大小
- **定时清理** — 清理过期的软删除数据

## [S12] 技术债务清单

1. **AsyncStorage → SQLite** — 最大性能瓶颈
2. **全量内存加载** — 大数据量时内存占用高
3. **Config 全量同步** — profiles.config 应拆分
4. **缺少 E2E 测试** — 关键流程无保障
5. **深色模式适配** — 部分组件未适配
